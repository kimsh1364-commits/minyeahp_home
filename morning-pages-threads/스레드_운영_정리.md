# 모닝페이지 스레드 운영 정리

## 1. 계정 방향

- **무엇을 하는 계정인가**: 모닝페이지(아침에 머릿속을 쏟아내는 습관)를 알리는 계정
- **최종 목표**: 말로 하는 모닝페이지 앱을 만들어서 판매
- **꼭 전하고 싶은 말**: **"손글씨가 귀찮으면 메모장도 괜찮다. 말로 해도 된다."**
  - 핵심은 손글씨가 아니라 아침에 머릿속을 한 번 쏟아내는 것
  - 원래 『아티스트 웨이』는 손으로 쓰라고 권한다는 건 부정하지 않기
    → "원래는 손으로지만, 귀찮아서 안 하는 것보단 메모장·말로가 낫다"
- **앱은 아직 홍보하지 않기**: 지금은 이 생각에 공감하는 사람을 모으는 단계. 앱이 나오면 "그래서 만들었어요"로 연결

## 2. 발행 일정

| 시간 | 종류 | 말투 |
|---|---|---|
| 오전 7시 | 정보성 (본글 + 답글) | 반말, "~한 사람들은 명심해" |
| 오후 9시 반 | 일상글 | 존댓말(~입니다, ~요) 또는 혼잣말체(~다) |

## 3. 정보성 글 공식

### 본글 4단 (각 2~3줄)

1. **콕 집어 부르기**: 눈에 보이는 상황 2~3개 나열 + "~한 사람들은 명심해"
2. **흔한 오해 깨기**: 다들 하는 방법이 왜 안 되는지 단호하게
3. **진짜 이유**: 원리 1~2문장
4. **예고**: 방법 개수를 **꼭 숫자로** — "딱 3가지만 따라 해봐!"
   - "이것만", "이대로"처럼 숫자 없는 예고는 쓰지 않기

### 답글 (방법)

1. 예고에서 말한 숫자와 **정확히 같은 개수**로 `1. 2. 3.` 번호 붙이기 (기본 3가지)
2. 덧붙일 팁은 번호를 늘리지 말고 해당 번호 아래 `(📌 ...)` 한 줄로
3. 기간·분량은 구체적으로 (예: "4주 동안은 다시 읽지 말고 덮기")
4. 마지막은 한 줄 정리 + 가볍게 대답할 수 있는 질문

## 4. 일상글 공식: "A가 B를 한다"

- **A** = 매일 아침 머릿속을 쏟아내는 나 (정체를 밝혀도, 숨겨도 됨)
- **B** = 아침 루틴 / 기분·감정 / 추천템 (모닝페이지 얘기가 아니어도 됨)
- 가르치지 않기. 그 사람이라서 보이는 장면 하나를 툭 던지기
- 질문으로 끝낼 필요 없음. **마지막 반전 한 줄**이 더 중요

### 유형 3가지

| 유형 | 구조 | 참고한 글 |
|---|---|---|
| 정체 + 관찰 + 반전 | 첫 줄에 정체 → 그 사람만 아는 관찰 → 마지막에 살짝 비틀기 | 소아치과 "결국.. 반지에서 나오더군요" |
| 정체 숨기고 장면만 | 장면 → 솔직한 감정 한 줄 → 엉뚱한 혼잣말 | 소아치과 "우리 친하잖아.." |
| 추천템 | 흥분한 첫 줄 → 제품명·산 곳 → 쓰는 법 → 써본 증거 → 자세한 건 답글 | 사과유자차 "2주 만에 한 통 다 먹었습니다😭" |

## 5. 쓰지 않는 것

- 호칭 "치니들", "너네" → **"사람들"**로
- 해본 적 없는 경험, 경력, 물건을 1인칭으로 지어내기
  - 일상글의 사실은 `data/persona.md`(나, 아침 루틴, 추천템)와 `data/notes.md`(있었던 일)에 적힌 것만
  - 추천템은 실제로 쓰는 물건만
- 연구 결과·수치·효과 기간을 사실처럼 쓰기 ("3주면 바뀐다" 등)
- "치료된다", "의학적으로" 같은 단정
- "히든 비법", "100% 효과" 같은 과장
- "내가 수십 번 말했지"처럼 하지 않은 과거 발언
- 링크, "댓글 달아주세요" 같은 대놓고 하는 부탁
- 앱 이름, 다운로드 언급 (출시 전까지)

## 6. 올리는 방법

| 방법 | 필요한 것 | 비고 |
|---|---|---|
| 직접 예약 게시 | 없음 | 이 문서 7번의 글을 복사해서 스레드 예약 또는 예약 도구로. 정보성은 본글 올린 뒤 답글로 방법 달기 |
| 자동발행 (미리 써둔 글) | Threads API | `data/queue.json`의 글을 순서대로 발행. Claude API 키 필요 없음 |
| 자동발행 (새로 쓰기) | Threads API + Claude API | 대기열이 비면 위 규칙대로 새 글을 써서 발행 |
